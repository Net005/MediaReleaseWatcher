# Core UI API contract

- `GET /api/actresses?q=...&group=...&upcoming_only=true` returns `{items: Actress[], total: number}`. Optional `upcoming_only` defaults false; true requires an actual persisted person/cast match with a nonempty release date strictly after today's UTC date. Identity-quarantined people, unknown dates, today, and past dates do not qualify. Existing q/group filters combine with this filter.
- `POST /api/actresses`: `{tmdb_id: string, name: string, group?: string, monitored?: boolean, auto_add?: boolean, notify?: boolean}`. New-watch defaults: monitored=true, auto_add=false, notify=false. Existing exact IDs return the existing watcher unchanged.
- `POST /api/actresses/import`: `{group?: string, monitored?: boolean, auto_add?: boolean, notify?: boolean, entries: [{actor_id: string, name: string, group?: string, monitored?: boolean, auto_add?: boolean, notify?: boolean}]}`. Literal positive numeric ID strings only. All entries validated before writes. Top-level fields are new-watch defaults; per-entry values win (including false/empty group). New-watch base defaults match add. First entry for an ID wins within a request; later duplicate IDs are ignored/counted skipped. Same-name/different-ID entries remain independent. Existing IDs retain name/group/monitored; only explicit per-entry auto_add/notify update existing preferences. Top-level defaults never overwrite existing opt-outs. Response `{added, skipped, queued, warning}`; skipped includes existing exact IDs and repeated input IDs, even when an existing ID's explicit flags were updated.
- `PATCH /api/actresses/{local_id}` accepts any explicit subset of `{group, monitored, auto_add, notify}` and returns Actress. New activations silently baseline known releases; newly discovered/future event transitions are eligible only with all relevant global/integration gates.
- `GET /api/mdblist/lists` returns `{items:[{id:string,name:string,enabled:boolean,monitored:boolean,auto_add:boolean}]}`. Settings `mdblist.lists` is authoritative, including `[]`. Omitted enabled defaults true; omitted monitored/auto_add default false. Legacy `list_ids` remains compatibility input.
- `GET /api/releases` supports `q,window,type,group,sort,actress_id,list_id,page,limit`; returns `{items,total,page,limit}`. `list_id` filters actual persisted membership, not cast. Release has `lists:[]` and `monitoring_origin: manual|list|actress|discovery`. `PATCH /api/releases/{id}` with `{monitored:boolean}` persists a manual override.
- `GET /api/releases/{id}/cast` returns `{items:[{tmdb_id,name,character,profile}],coverage:string}` using actual provider records only. No fabricated missing names. `GET /api/people/{tmdb_person_id}` returns `{person:Actress,releases:Release[]}`; person lookup does not create a watcher. Cast cards must use TMDb person IDs, not local watcher IDs.
- Settings `silo:{url,enabled,configured,api_key?}`; key is input-only/redacted in reads, blank preserves stored key. Silo/scheduler/Arr/watchlist routes are registered once through the parent-owned upgrade route helper.
